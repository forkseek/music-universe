## 1. 依据与当前状态

- 以用户最新提供的《Music World 开发指令》0–30 节为项目规则，原文保存在 `PROJECT_RULES.md`。
- 项目已落地为 Next.js 16 + TypeScript + SQLite/Drizzle 应用，文件与 Demo 导入、地图、五站 Journey、持久化、事实 Guide 和模型失败回退均可在本机运行。当前处于视觉打磨与提交材料准备阶段。
- 用户已明确要求模型先保留接口，暂不接入真实服务；目前的自然语言路线由真实导入标签驱动的基础算法生成，不将其宣称为模型调用。
- 交付目标是音乐平台无关的音乐探索层：从音乐资产出发，理解关系，生成可探索地图与 Journey。
- QQ 音乐真实接入取决于官方权限与支持的运行环境；该依赖不阻断文件导入和 Demo 验收。

## 2. MVP 验收主线

首页选择文件或 Demo → 构建音乐库 → 生成 15–30 个主要节点的世界 → 缩放、拖动和点击 → 查看关系解释 → 从当前节点发起 Journey → 生成 5 首歌曲的路线 → 地图高亮路线。

当音乐库不足 15 个可用节点或不足 5 首不同歌曲时，展示实际数量并说明原因，不编造歌曲、不重复凑数；标准演示数据必须满足完整 5 首路线。

首页使用 `Build My Music World`；Demo 明确标记 `Demo Music Library`。播放入口打开来源平台页面。

## 3. 技术决策

| 层 | 本轮决定 |
| --- | --- |

## 4. 架构与数据流

```text
文件 / Demo / 获授权的官方 SDK
            ↓
Music Provider Adapter Layer
            ↓
ProviderTrack → 标准化 → 去重与来源合并
            ↓
SQLite 音乐库 + 用户音乐信号
            ↓
确定性 Music Graph → 有限节点投影 → Music World
            ↓
候选歌曲 → Journey Planner → 路线与逐站解释
            ↑
AI Provider + Zod 校验 + 失败回退
```

QQ SDK 的存在与授权状态由浏览器在适配层内检查；服务端 `/api/providers` 提供配置和能力信息，不能以服务端是否存在 `window` 判定用户浏览器环境。QQ 导入接口负责验证、标准化和保存获授权 SDK 返回的数据。

## 5. 开工前固定的数据约定

1. 内部 Track、Artist、Album、World、Journey 等实体使用自己的 UUID；平台 ID 只存于来源记录。
2. 补充文档示例未完整列出的 ISRC、canonicalKey 和经筛选的原始 metadata 字段。单条导入记录保留 source，合并后的 Track 通过 TrackSource 保存多个来源。
3. 去重按文档优先级执行，并保护 Live、Remix、不同录音等版本信息。证据冲突或身份有歧义时保留独立记录，不能因为标题相似就强制合并。
4. 保留原始 metadata 时使用字段白名单；凭证、完整歌曲音频地址及 DRM 信息不落库。来源网页 URL 与音频播放 URL 分别处理。
5. UserTrackSignal 仅根据真实导入字段计算；未知收藏或播放状态保持未知，不能把“出现在文件里”直接视作收藏。
6. 用户输入、Provider 数据和模型输出都在进入业务层前校验。上传大小、记录数、字符串长度和模型耗时有明确上限。
7. 地图节点允许艺术家、歌曲、专辑和流派；Journey 固定为可解析到真实 Track 的歌曲路线。艺术家起点先映射到库中歌曲，沿途歌曲必须能在地图中定位或展开显示。
8. 第一版无注册登录流程，但通过匿名会话隔离用户导入数据、世界和路线；持有某个 worldId 不自动获得其他用户数据的访问权。
9. 删除音乐库时，删除当前匿名会话的导入数据和派生世界、路线；保留应用自带 Demo 模板以及其他会话数据。

## 6. 严格开发顺序与阶段验收

| 顺序 | 工作 | 可验收产物 |
| --- | --- | --- |
| 1 | Provider Interface | 定义统一类型、能力、可用状态、错误及注册表；平台字段不会泄漏到 Graph 和 Journey |
| 2 | File Provider | CSV / JSON / TXT 解析；错误行反馈；提供可下载样例；同阶段准备 50–100 首、20–30 位艺术家的 Demo 固定数据 |
| 3 | Normalizer | 字符标准化、字段映射、UUID、ISRC、canonicalKey、来源及原始元数据保留策略 |
| 4 | Deduplication | 跨来源合并、版本保护、重复导入不累加重复歌曲或来源；输出导入统计 |
| 5 | Database | 建立文档要求的数据实体和关系；完成迁移、会话归属、导入保存与删除 |
| 6 | Music Graph | 确定性关系、偏好权重、聚类与有限节点投影；100 首歌曲不会直接铺成 100 个主要节点 |
| 7 | Music World UI | 首页、导入反馈、世界页面、音乐卡片；可缩放、拖动、点击，关系理由可见 |
| 8 | Journey | 先完成确定性规划和路径高亮，再加入模型规划；落库、详情页、起点和逐站理由完整 |
| 9 | AI Guide | 使用当前节点、候选邻居、画像和路线理解意图；返回结构化结果并更新路线，不重建音乐库 |
| 10 | QQ Music Official Adapter | 核对官方文档和环境要求；开关、SDK 检测、真实授权状态、分页及明确不可用状态 |
| 11 | UI Polish | 路径与节点反馈、加载/空/错误状态、可读性、桌面演示画面与最终演示材料 |

每一阶段先通过验收再进入依赖它的阶段。数据样例、文案和演示材料可以同步准备。

## 7. Journey 与 AI 的可靠性

- 候选集合来自当前世界可访问的真实歌曲；模型只选择已有 ID，并解释路径。
- 除 Zod 结构校验，还检查 ID 是否存在、是否属于当前世界、节点是否重复、起点是否正确、长度是否合理。
- JSON 或结构校验失败重试一次；再次失败自动使用确定性 Graph 路线。网络失败、超时或缺少模型密钥时也能回退。
- 确定性规划使用已有关系、用户偏好、目标标签和访问历史；保证示例库中的标准演示路线可用。
- AI 补充情绪、风格、主题和推荐说明。未经来源验证的历史影响不作为事实关系保存。
- AI Guide 推荐节点也限定在候选集合内；显示采用的运行模式，演示算法回退不得假称模型已经调用成功。

## 8. 页面与 API 交付范围

页面遵循最新规则的目录：`/`、`/world/[worldId]`、`/journey/[journeyId]`。

首页：音乐来源、文件导入、Try Demo、真实 Provider 状态。

世界页：地图、关系解释、Music Card、JourneyPanel、AI Guide、来源平台链接。

Journey 详情页：起点、意图、5 站路线、逐站说明，以及返回世界查看高亮路径。

必须交付的接口：

```text
GET    /api/providers
POST   /api/imports/file
POST   /api/imports/qqmusic
POST   /api/music/normalize
POST   /api/worlds
GET    /api/worlds/:id
POST   /api/journeys
GET    /api/journeys/:id
DELETE /api/library
```

补充 Demo 导入和 AI Guide 所需的内部入口，沿用相同验证、归属与错误处理约定。实际路径在实现时统一，不将平台 API 暴露为业务依赖。

## 10. 验证清单

- QQ SDK 缺失、开关关闭或授权不可用时，页面正常工作且状态真实。
- 官方适配的分页逻辑用替身 SDK 测试超过 30 首的情况，以及空页、重复页和中途失败；只有在真实环境运行过才能标记为“官方接入已验证”。分页起点等细节以核实后的官方约定为准。
- CSV / JSON / TXT 成功导入，空文件、乱码、坏格式和超限内容提供清楚反馈。
- 同曲跨来源合并、重复导入保持幂等；不同版本不会被错误吞并。
- 100 首样例歌曲生成有限地图节点；地图点击可查看真实元数据与关系理由。
- 标准演示路线包含 5 首不同的有效歌曲，起点正确，地图高亮与路线顺序一致。
- 非法 JSON、无效 ID、模型超时和无密钥场景能够回退。
- 导入、刷新、重新打开世界和 Journey 后数据仍然存在。
- 两个匿名会话不能读取或删除彼此的数据；删除后当前会话的派生数据同步移除。
- 类型检查、必要的单元/集成检查和正式构建通过；浏览器实测完整用户链路。

## 11. 演示与最终交付

主演示：选择明确标注的 Demo 或导入示例文件 → 地图展开 → 点击 Radiohead 或 Slowdive → 查看连接理由 → 输入“更梦幻一点” → 创建 5 站 Journey → 路径亮起 → 打开歌曲来源页面。

交付内容：可运行源码、依赖锁文件、数据库迁移与初始化、导入样例、Demo 数据、环境变量示例、运行/测试/部署说明、测试结果、演示截图与视频。

验收除流程成功外，还保留原始产品目标：用户能在 10 秒内理解音乐世界，愿意继续点击节点，并理解音乐之间的连接原因。
