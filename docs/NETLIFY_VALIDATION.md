# Netlify 发布分支验证记录

日期：2026-10-08。分支：`codex/netlify-neon`。本文件区分本地生产测试、实际数据库验证和待完成的公网发布。

## 已完成

- 根工程完整测试 184 项通过；最后调整音频响应边界后，平台与云端状态相关 15 项复验通过。ESLint 和 TypeScript 检查通过。
- Next.js 正式构建通过，包括 Vite/R3F 星系资源。Netlify 使用官方 `--webpack` 构建选项，避免本机 Windows 的目录符号链接复制限制。
- GitHub Linux 环境完成官方 Netlify 构建：Next.js、后台函数和边缘函数打包均通过；函数 ZIP 内包含音乐 worker、数据库迁移，未发现个人环境文件。见 [Linux 构建记录](https://github.com/forkseek/music-universe/actions/runs/37781722312)，对应代码提交 `73dee6e9d9a6f36ed943fa3f940103aff9be6dc3`。此检查没有使用云端凭据，也没有发布网站。
- 真实 Neon Free 数据库已使用 TLS 连接，19 张表的迁移、临时表读写检查通过。没有复制本机账号或音乐库。
- 两个独立生产进程连接同一隔离 PostgreSQL 协议测试数据库，扫码状态、搜索元数据、播放票据和退出失效能跨进程接续。模拟的扫码授权不代表真实用户登录。
- 打包后的真实音乐 worker 能加载依赖。1214 个音乐运行依赖被纳入 Next 文件追踪。
- 原生 Chromium 完整播放 26,880,044 字节、70 秒的自制 WAV；浏览器发出 7 次分段请求，每段不超过 4 MiB。进度拖动有效，过大的未分段请求明确拒绝。
- 生产大厅进入同站点 3D 星系，WebGL、字体和资源验证通过。
- 现有自动下一首浏览器验收全部通过：按序切换、预缓冲、失败重试、重复结束事件、末首循环、手动操作优先、暂停不切歌、本地未识别文件不启动无关专辑。测试音切换间隔约 231 ms，歌词、镜头和沉浸 Canvas 保持同步。这不代表真实平台网络延迟。
- 本地验证输出在 `test-results/` 和星系的测试报告目录，均不提交到 GitHub。测试使用隔离数据和明确标记的模拟平台返回。

## 发布前检查

- Netlify 官方适配器已通过 Linux 完整打包。本机 Windows 的边缘打包存在路径兼容错误，因此正式部署必须由 Linux 云端构建。不能把打包成功视作公网发布成功。
- Linux 检查发现默认专辑文件曾被旧 `data/` 忽略规则漏传，已将规则限定为根目录 `/data/` 并补齐源码，重新构建通过。
- 原有 Render 分支与原来两个本地工程保留。发布分支新增的数据库迁移仅增加短期状态表，不删除原表。
- `.env`、数据库连接、加密密钥及云平台授权文件不进入仓库或发布包。

## 公网尚待验证

尚未创建 Netlify 站点或取得公开网址。需要用户的 Netlify 账号授权，并单独允许把已有 Neon 连接和应用加密密钥配置到 Netlify 的后台环境变量；先前针对 Render 的授权不自动扩展到 Netlify。

发布后继续检查实际 HTTPS 健康接口、匿名会话、数据库唤醒、真实搜索和本人手机扫码、昵称头像、合法可播放音源、歌词和连续切歌。未配置 QQ 官方应用时，不宣称 QQ 登录或播放授权完成。桌面 Electron 登录不在此云端方案范围内。

Free 计划有额度和单次函数限制。不得自动升级付费计划或开启自动充值，具体限制见 [部署说明](DEPLOY_NETLIFY_NEON.md)。原 Render 分支的历史验证记录保留在 [DEPLOYMENT_VALIDATION.md](DEPLOYMENT_VALIDATION.md)。
